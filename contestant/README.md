# 自测网站使用说明

网址：https://arcbench-selftest-web.vercel.app

## 这是什么

把你做好的 app 打包上传，几分钟内拿到一个「通过/失败」的测试结果，**只给你自己看**。
这不是正式评测，不计入成绩，也不上任何榜，纯粹用来自己检查代码能不能跑、测试能不能过。

## 怎么用

1. 打开网站，用 GitHub 账号登录。
2. 在任务列表里选一个题目。
3. 上传你打包好的 zip。
4. 页面会自动轮询，等结果出来（通常几分钟），看每条测试是通过还是失败，失败的会带报错文字（除非该题目结果是隐藏的，那样只显示通过数）。

## 每天能测几次

- 每人每天最多 **10 次**提交。
- 全站每天有总次数上限，极端情况下可能排到第二天。
- GitHub 账号太新（注册不到 7 天）暂时不能提交。

## zip 要求

- zip 根目录必须直接有一个 `Dockerfile`（不能嵌在子文件夹里）。
- 不要用软链接，不要有 `../` 之类跳出目录的路径。
- 解压后总大小不超过 50MB，文件数不超过 2000 个。
- 你的 app 必须监听环境变量 `$PORT`（没有就默认监听 3000），不要自己硬编码别的端口。

打包模板和脚本见 [`template/`](./template/) 目录。

## 常见失败原因 & 怎么看报错

提交后进详情页，看 `status`：

- `queued` / `running`：还在排队或跑测试，等着就行。
- `passed` / `failed`：跑完了。每条测试后面的红字就是具体报错（断言失败、超时等），对着改代码。
- `error`：没跑到测试这一步，通常是以下几种，看页面上的 `detail` 文字：
  - `not a zip file` / `zip exceeds 50MB` / 上传相关报错 → 检查打包方式，用 `template/pack.sh` 重新打包。
  - `unknown task` → 题目 id 填错了，回任务列表重新点进去提交。
  - `daily submission limit reached` → 当天次数用完了，明天再来。
  - `app did not become ready within Ns` → app 启动太慢，或者没有监听 `$PORT`，本地先用 `docker build . && docker run -e PORT=3000 -p 3000:3000 <image>` 跑一下确认能访问。
  - `app build failed` → Dockerfile 本身 build 不过，本地先 `docker build .` 确认能过。

## 评测系统出错了怎么办

如果页面长时间卡在 `queued` 不动，或者报错看起来明显不是你代码的问题（比如系统内部错误），
先刷新页面重新看一次结果，然后把题目名、提交时间、报错截图发到选手群，找工作人员处理，不用自己反复重试刷次数。
