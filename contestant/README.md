# 自测网站使用说明

网址：https://arcbench-selftest-web.vercel.app

## 用途

上传你写好的 app，使用与正式评测相同的环境跑一遍测试，几分钟内查看结果。结果仅提交者本人可见，不计入成绩，不进入排行榜。

## 使用步骤

1. 使用 GitHub 账号登录。
2. 在题目列表中选择一道题目。
3. 上传打包好的 zip 文件。
4. 等待评测完成，查看每条测试的通过情况；未通过的测试可展开查看报错信息。

## 使用限制

- 每人每天最多提交 10 次，次日 UTC 0 点重置。
- 评测系统自身出错的提交不计入次数。
- 全站每天有总提交上限，达到后次日再试。
- 新注册的 GitHub 账号（不足 7 天）暂时无法使用。

## zip 格式要求

- zip 根目录需直接包含 `Dockerfile`，不能放在子文件夹中。
- 不允许软链接，不允许路径中出现跳出目录的 `../`。
- 解压后总大小不超过 50MB，文件数不超过 2000 个。
- app 需监听环境变量 `PORT`（未设置时默认 3000），不要硬编码其他端口。

打包模板见 [`template/`](./template/) 目录。

## 常见错误

- 文件超过 50MB：删除 `node_modules`、构建产物等后重新打包。
- 不是有效的 zip 文件：用 `template/pack.sh` 或等效方式重新打包。
- 找不到题目：返回题目列表重新选择后再提交。
- 今日次数已用完：次日 UTC 0 点重置后再试。
- app 未能在规定时间内就绪：确认容器监听 `PORT` 环境变量；可在本地用
  `docker build . && docker run -e PORT=3000 -p 3000:3000 <image>` 验证后再上传。
- app 构建失败：先在本地执行 `docker build .` 确认能构建成功。

## 评测系统出错时

此类提交显示为系统出错，不计入当日次数，可直接重新提交。若反复出现，记录题目名称和提交时间，反馈给工作人员处理。
